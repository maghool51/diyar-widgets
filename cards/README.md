# کارت‌پستال دیجیتال دیار قدمگاه — `/cards`

ماژول مستقل، بدون Backend و کاملاً Client-side برای ساخت و اشتراک‌گذاری
کارت‌پستال دیجیتال. با معماری Data-Driven: افزودن مناسبت/طرح/متن جدید
فقط با ویرایش فایل‌های JSON داخل `data/` انجام می‌شود، بدون نیاز به
تغییر کد.

## مسیر استفاده

```
maghool51.github.io/diyar-widgets/cards/
```

مثل بقیه‌ی ویجت‌های این مخزن (`hadith/`, `player/`, ...)، این پوشه کاملاً
مستقل است و به هیچ فایل دیگری در ریشه‌ی مخزن وابسته نیست.

## ساختار پوشه‌ها

```
cards/
├── index.html          صفحه‌ی اصلی (هم Builder، هم Viewer لینک‌های اشتراکی)
├── css/
│   ├── base.css         پوسته‌ی برنامه (Wizard، فرم، دکمه‌ها)
│   ├── palettes.css      پالت‌های رنگی کارت (--c-* variables)
│   └── layouts.css       ساختارهای بصری کارت (Layoutها)
├── js/
│   ├── core/
│   │   ├── utils.js        کمکی‌های DOM/متن (sanitize, textContent-only)
│   │   ├── state.js         Store مرکزی
│   │   ├── url.js            تبدیل state ↔ Query String کوتاه
│   │   ├── share.js          Web Share API + کپی کلیپ‌بورد
│   │   ├── export-png.js     خروجی PNG بدون کتابخانه‌ی خارجی
│   │   └── render.js         ساخت مارک‌آپ کارت و شبکه‌های انتخاب
│   ├── data-loader.js       خواندن فایل‌های data/*.json
│   └── main.js               اتصال همه‌چیز به هم (Wizard + Viewer)
└── data/
    ├── categories.json      مناسبت‌های سطح اول + دسته‌های مذهبی
    ├── occasions.json       نام‌های خاص مذهبی/ملی (میلاد، شهادت، ...)
    ├── templates.json       طرح‌های بصری هر گروه (Layout + Palette)
    └── messages.json        متن‌های آماده به تفکیک هر گروه
```

## چگونگی افزودن یک طرح (Template) جدید

هیچ کدی لازم نیست. یک آبجکت جدید به آرایه‌ی گروه مربوطه در
`data/templates.json` اضافه کنید:

```json
{ "id": "birthday-jadid", "title": "طرح جدید", "layout": "banner-top", "palette": "gold", "icon": "🎈" }
```

- `layout` باید یکی از کلاس‌های موجود در `css/layouts.css` باشد
  (در حال حاضر ۱۲ طرح: `classic-center`, `banner-top`, `split`,
  `floral-corners`, `badge-medal`, `ticket-stub`, `mourning-veil`,
  `gold-frame`, `family-warm`, `minimal-line`, `wave-bottom`,
  `emotional-soft`).
- `palette` باید یکی از کلاس‌های موجود در `css/palettes.css` باشد
  (۱۲ پالت: `emerald`, `gold`, `navy`, `rose`, `sky`, `terracotta`,
  `plum`, `forest`, `slate`, `blush`, `lavender`, `charcoal`).
- `id` باید در کل فایل یکتا باشد (چون در لینک اشتراک‌گذاری استفاده
  می‌شود).

برای یک **ترکیب‌بندی کاملاً جدید** (نه صرفاً رنگ)، یک بلوک
`[data-layout='نام-جدید']` در `css/layouts.css` اضافه کنید که روی
`.dq-card__orn-a` و `.dq-card__orn-b` (دو المان تزئینی آماده) استایل
می‌دهد — به همین دو المان محدود کنید تا با موتور خروجی PNG سازگار
بماند.

## چگونگی افزودن یک دسته‌بندی جدید

یک آبجکت به آرایه‌ی `categories` در `data/categories.json` اضافه
کنید:

```json
{ "id": "new-cat", "title": "عنوان فارسی", "icon": "🌟", "templateGroup": "congrats" }
```

اگر دسته باید مثل «مناسبت‌های ملی» ابتدا یک لیست مناسبت خاص نشان دهد،
`"hasOccasions": true` اضافه کنید و لیست را در `data/occasions.json`
با همان `id` دسته تعریف کنید. برای زیردسته‌های مذهبی، آبجکت را در
`religiousSubcategories` اضافه کنید.

## چگونگی افزودن متن آماده‌ی جدید

یک آبجکت `{ "style": "...", "text": "..." }` به آرایه‌ی مربوط به
`templateGroup` در `data/messages.json` اضافه کنید.

## سیستم URL

اطلاعات کارت (نه پیام‌های آماده، بلکه محتوای واقعی که کاربر ساخته) در
Query String صفحه کدگذاری می‌شود؛ چون Backend نداریم، این تنها راه
اشتراک‌گذاری بدون سرور است:

| کلید | معنی |
|---|---|
| `t` | شناسه‌ی طرح (Template) — تنها فیلد ضروری برای نمایش صحیح کارت |
| `r` | نام گیرنده |
| `g` | عنوان |
| `m` | متن پیام |
| `f` | نام فرستنده |
| `c`, `o` | دسته/مناسبت انتخاب‌شده (فقط برای اطلاع، در نمایش کارت استفاده نمی‌شود) |

وقتی کسی لینک را باز می‌کند، `main.js` تشخیص می‌دهد که پارامتر `t`
وجود دارد و به‌جای Wizard، مستقیماً «حالت مشاهده» (Viewer) را نشان
می‌دهد.

## خروجی PNG — محدودیت شناخته‌شده

`core/export-png.js` بدون هیچ کتابخانه‌ی خارجی کار می‌کند (کپی
Computed Style روی یک SVG `foreignObject` و رسم روی Canvas). برای اکثر
Layoutها نتیجه تمیز است؛ اگر در آینده افکت‌های CSS پیچیده‌تری
(مثل `backdrop-filter`) اضافه شود، ممکن است نیاز به یک راهکار
قوی‌تر (مثل بارگذاری اختیاری `html-to-image` فقط در همین صفحه) باشد.

## آماده برای تقویم مناسبتی (گام بعدی، هنوز پیاده نشده)

هر آیتم در `occasions.json` می‌تواند بعداً یک فیلد `date` بگیرد تا
سیستم بتواند بر اساس تاریخ روز، کارت مناسبتی پیشنهاد دهد. فعلاً این
فیلد وجود ندارد — طبق تصمیم صریح در فاز اول.

## موسیقی (گام بعدی، هنوز پیاده نشده)

می‌توان به هر ورودی `templates.json` فیلد اختیاری `"music": "..."`
اضافه کرد و در `main.js` هنگام ساخت پیش‌نمایش، در صورت وجود، پخش
اختیاری (با دکمه‌ی روشن/خاموش، نه Autoplay) اضافه کرد.
