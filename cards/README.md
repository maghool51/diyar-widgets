# کارت‌پستال دیجیتال دیار قدمگاه — `/cards`

ماژول مستقل، بدون Backend و کاملاً Client-side برای ساخت و اشتراک‌گذاری
کارت‌پستال دیجیتال. با معماری Data-Driven: افزودن مناسبت/طرح/متن جدید
فقط با ویرایش فایل‌های JSON داخل `data/` انجام می‌شود، بدون نیاز به
تغییر کد.

## مسیر استفاده

```
maghool51.github.io/diyar-widgets/cards/
```

مثل بقیه‌ی ویجت‌های این مخزن (`hadith/`, `player/`, ...)، این پوشه کاملاً
مستقل است و به هیچ فایل دیگری در ریشه‌ی مخزن وابسته نیست.

## چگونگی افزودن یک طرح (Template) جدید

هیچ کدی لازم نیست. یک آبجکت جدید به آرایه‌ی گروه مربوطه در
`data/templates.json` اضافه کنید:

```json
{ "id": "birthday-jadid", "title": "طرح جدید", "layout": "banner-top", "palette": "gold", "icon": "🎈" }
```

- `layout` باید یکی از کلاس‌های موجود در `css/layouts.css` باشد
  (در حال حاضر ۱۲ طرح: `classic-center`, `banner-top`, `split`,
  `floral-corners`, `badge-medal`, `ticket-stub`, `mourning-veil`,
  `gold-frame`, `family-warm`, `minimal-line`, `wave-bottom`,
  `emotional-soft`).
- `palette` باید یکی از کلاس‌های موجود در `css/palettes.css` باشد
  (۱۲ پالت: `emerald`, `gold`, `navy`, `rose`, `sky`, `terracotta`,
  `plum`, `forest`, `slate`, `blush`, `lavender`, `charcoal`).
- `id` باید در کل فایل یکتا باشد (چون در لینک اشتراک‌گذاری استفاده
  می‌شود).

برای یک **ترکیب‌بندی کاملاً جدید** (نه صرفاً رنگ)، یک بلوک
`[data-layout='نام-جدید']` در `css/layouts.css` اضافه کنید که روی
`.dq-card__orn-a` و `.dq-card__orn-b` (دو المان تزئینی آماده) استایل
می‌دهد — به همین دو المان محدود کنید تا با موتور خروجی PNG سازگار
بماند.

## چگونگی افزودن یک دسته‌بندی جدید

یک آبجکت به آرایه‌ی `categories` در `data/categories.json` اضافه
کنید:

```json
{ "id": "new-cat", "title": "عنوان فارسی", "icon": "🌟", "templateGroup": "congrats" }
```

اگر دسته باید مثل «مناسبت‌های ملی» ابتدا یک لیست مناسبت خاص نشان دهد،
`"hasOccasions": true` اضافه کنید و لیست را در `data/occasions.json`
با همان `id` دسته تعریف کنید. برای زیردسته‌های مذهبی، آبجکت را در
`religiousSubcategories` اضافه کنید.

## چگونگی افزودن متن آماده‌ی جدید

یک آبجکت `{ "style": "...", "text": "..." }` به آرایه‌ی مربوط به
`templateGroup` در `data/messages.json` اضافه کنید.

## سیستم URL

اطلاعات کارت (نه پیام‌های آماده، بلکه محتوای واقعی که کاربر ساخته) در
Query String صفحه کدگذاری می‌شود؛ چون Backend نداریم، این تنها راه
اشتراک‌گذاری بدون سرور است:

| کلید | معنی |
|---|---|
| `t` | شناسه‌ی طرح (Template) — تنها فیلد ضروری برای نمایش صحیح کارت |
| `r` | نام گیرنده |
| `g` | عنوان |
| `m` | متن پیام |
| `f` | نام فرستنده |
| `c`, `o` | دسته/مناسبت انتخاب‌شده (فقط برای اطلاع، در نمایش کارت استفاده نمی‌شود) |

وقتی کسی لینک را باز می‌کند، `main.js` تشخیص می‌دهد که پارامتر `t`
وجود دارد و به‌جای Wizard، مستقیماً «حالت مشاهده» (Viewer) را نشان
می‌دهد.

## خروجی PNG — محدودیت شناخته‌شده

`core/export-png.js` بدون هیچ کتابخانه‌ی خارجی کار می‌کند (کپی
Computed Style روی یک SVG `foreignObject` و رسم روی Canvas). برای اکثر
Layoutها نتیجه تمیز است؛ اگر در آینده افکت‌های CSS پیچیده‌تری
(مثل `backdrop-filter`) اضافه شود، ممکن است نیاز به یک راهکار
قوی‌تر (مثل بارگذاری اختیاری `html-to-image` فقط در همین صفحه) باشد.

## آماده برای تقویم مناسبتی (گام بعدی، هنوز پیاده نشده)

هر آیتم در `occasions.json` می‌تواند بعداً یک فیلد `date` بگیرد تا
سیستم بتواند بر اساس تاریخ روز، کارت مناسبتی پیشنهاد دهد. فعلاً این
فیلد وجود ندارد — طبق تصمیم صریح در فاز اول.

## موسیقی و جلوه‌های بصری (روی هر ۵۳ Template پیاده‌شده)

هر Template می‌تواند فیلدهای اختیاری زیر را داشته باشد که هیچ‌کدام روی
Templateهای دیگر اثری ندارند (پیش‌فرض: خالی = بدون تغییر):

- `"headline"` — یک خط عنوان مناسبت بالای کارت (مثلاً «تولدت مبارک 🎉»)، هم در Live Preview و هم در نمایش نهایی دیده می‌شود. هر یک از ۱۷ گروه Template متن مخصوص به خودش را دارد.
- `"effects"` — کلید یکی از ۵ مجموعه‌جلوه‌ی تعریف‌شده در `js/core/effects.js`، هرکدام متناسب با حال‌وهوای دسته‌ی خودشان:
  - `"birthday-confetti"` — بادکنک، ستاره، ذرات نور، چند قلب ظریف، کنفتی، Glow (تولد، تولد فرزند)
  - `"celebration-stars"` — ستاره + کنفتی کم‌رنگ‌تر، بدون بادکنک/قلب (تبریک، موفقیت، خوشامدگویی، خانه‌ی جدید، مناسبت‌های ملی)
  - `"romantic-soft"` — قلب‌های ظریف + جرقه‌ی نور، بدون کنفتی/بادکنک (ازدواج، سالگرد)
  - `"gentle-glow"` — فقط چند ستاره‌ی کم‌رنگ و باوقار (میلاد، مبعث، اعیاد مذهبی، خداحافظی)
  - `"somber-light"` — **عمداً خالی از هر ذره‌ای** (سوگواری، تسلیت، شهادت، رحلت) — فقط همان درخشش ملایم پایه‌ی کارت، بدون کنفتی/بادکنک/ستاره/قلب، چون این مناسبت‌ها نباید جشن‌گونه به‌نظر برسند.
  با `prefers-reduced-motion` همه‌ی این‌ها به‌طور کامل غیرفعال می‌شوند.
- `"music"` — سه حال‌وهوای تولیدی (`js/core/music.js`، بدون فایل خارجی، بدون مسئله‌ی کپی‌رایت) به‌علاوه‌ی امکان فایل واقعی:
  - `"generated"` — ملودی شاد و پرانرژی (تولد، تبریک، موفقیت، خوشامدگویی، مناسبت‌های ملی)
  - `"generated-warm"` — ملودی گرم و کندتر (ازدواج، سالگرد، تولد فرزند، خانه‌ی جدید، خداحافظی)
  - `"generated-solemn"` — ملودی بسیار ساده، آرام و کم‌صدا (میلاد، مبعث، اعیاد مذهبی)
  - یک مسیر/URL فایل صوتی واقعی، مثلاً `"assets/music/birthday.mp3"` — به‌جای Web Audio، با `<audio loop>` و Fade-in پخش می‌شود. جزئیات در `assets/music/README.md`.
  - **گروه‌های سوگواری/تسلیت/شهادت/رحلت عمداً هیچ `"music"` ندارند** (نه یک مقدار خالی — کل کلید حذف شده) چون پخش موسیقی برای این مناسبت‌ها نامناسب است؛ دکمه‌ی موسیقی برایشان اصلاً ساخته نمی‌شود.
  - شروع پخش همیشه از داخل خودِ لمس پاکت است (نه بعد از تأخیر)، چون مرورگرها Autoplay بدون تعامل را مسدود می‌کنند؛ اگر مرورگر (مثلاً برخی WebViewهای داخل‌اپ) حتی بعد از تعامل هم اجازه‌ی پخش ندهد، دکمه به‌جای گیر کردن پیام «پخش موسیقی در این مرورگر ممکن نیست» را نشان می‌دهد.

افزودن این فیلدها به Template دیگری فقط با ویرایش `data/templates.json`
انجام می‌شود — نیازی به تغییر کد نیست، مگر بخواهید یک مجموعه‌جلوه یا
حال‌وهوای موسیقیِ کاملاً جدید تعریف کنید (به‌ترتیب: یک تابع جدید در
`EFFECT_BUILDERS` داخل `effects.js`، یا یک ورودی جدید در `MOODS` داخل
`music.js`).

## تجربه‌ی سینمایی «پاکت» (Experience، روی هر ۵۳ Template پیاده‌شده)

اگر یک Template فیلد `"experience": "envelope"` داشته باشد، به‌جای
نمایش مستقیم کارت، `js/core/experience.js` این توالی را اجرا می‌کند
(هماهنگ با `render.js` + `effects.js` + `music.js`، بدون کد تکراری):

```
پاکت وارد صحنه می‌شود (Scale+Rotate+Fade)
   ↓  (کاربر لمس می‌کند)
راهنما محو می‌شود + Flap باز می‌شود + موسیقی همان لحظه شروع می‌شود + جرقه‌ی نور
   ↓
کارت از پاکت بیرون می‌آید (Emerge: Translate+Rotate+Scale، با Bounce ظریف)
   ↓
کارت باز می‌شود (Unfold: ScaleY)
   ↓
عنوان → آیکون → گیرنده → خطاب → پیام → فرستنده به‌ترتیب Fade+Slide می‌شوند
   ↓
جلوه‌های ویژه‌ی مناسبت (فیلد effects) اجرا می‌شوند
```

نکات معماری مهم:

- **هرگز صفحه‌ی خالی**: اگر `experience` تعریف نشده باشد (Templateهای آینده که هنوز مجهز نشده‌اند)، یا `prefers-reduced-motion: reduce` فعال باشد، یا هر خطای غیرمنتظره‌ای رخ دهد، بلافاصله همان کارت باز و کامل (بدون پاکت) نمایش داده می‌شود.
- فقط از `transform`/`opacity` برای انیمیشن استفاده شده (نه
  top/left/width/height) — سبک روی موبایل.
- انیمیشن‌ها با رویداد واقعی `animationend` به هم زنجیر شده‌اند (نه
  `setTimeout` حدسی) تا با سرعت واقعی دستگاه هماهنگ بمانند.
- برای تعریف تجربه‌ی اختصاصی یک مناسبت دیگر (مثلاً عروسی)، یک تابع
  جدید به `EXPERIENCE_BUILDERS` در `experience.js` اضافه کنید و
  `"experience"` را در `templates.json` به همان کلید تنظیم کنید.
